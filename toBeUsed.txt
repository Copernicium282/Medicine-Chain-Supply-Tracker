BASIC IDEA OF THIS PROJECT:

Description
This project focuses on building a web-based, transparent and tamper-evident medicine
supply chain tracking system that registers the entire history or journey of batches of
medicine onto a log backed by a hash-linked simulated blockchain, where the hashes are
generated and linked to prevent counterfeit drugs from entering the distribution network.
Each batch begins with a genesis block created by the manufacturer, and every update
forms a new block linked to the previous one. Manufacturers, Distributors, Pharmacies,
and Admins can log in using either Firebase or Metamask Authentication. A public QR-
based verification page is available for anyone, displaying the entire journey of the scanned
batch, recomputing all hashes to verify chain integrity and ensuring full transparency and
traceability.
Features
• Batch Creation: Manufacturers can register new medicine batches in the log by
providing the required details, such as quantity, production date, and expiry date,
and uploading the necessary verification certificates. A genesis block is created using
CryptoJS SHA-256 hashing, where the previous hash is set to ‘0’, and the current
hash is generated from the batch registration data, and a QR code is generated for
public verification.
• Shipment Tracking: Distributors can append each batch shipment or transport
details onto the log (which is used to generate a new block hashed and linked to
the genesis block with CryptoJS) by filling in required details like sender, reciever
details, quantity of medicine in the batch, timestamps for arrival and departure
of the batch, and other transport details, and evidence documents for verification.
Linking of Distributor data block to the Manufacturer’s genesis block on the simu-
lated blockchain prevents counterfeit drugs from entering the transportation system
and ensures clear traceability.
• Receipt Confirmation: Pharmacies confirm delivery and update the status of
batches in the log, creating a new block linked to the Distributor data block on the
simulated blockchain, hashed and linked via CryptoJS, preserving the integrity of
the supply chain record.
• User Authentication: Role-based authentication for manufacturers, distributors,
pharmacies, and admins using either Firebase Authentication or Metamask Authen-
tication, which allows for both secure authentication as well as a decentralised way
of identity verification.
• Enhanced Security: Each event is stored as a SHA-256 hashed entry linked to the
previous hash, and a verification program recomputes all hashes to detect any break
in the hash chain and triggers tamper alerts to maintain data integrity, ensuring a
transparent and secure history.
• Public QR Verification: Anyone can scan the QR code or enter the Batch ID to
view the entire journey of the batch and verify the chain integrity.
• Advanced Dashboards: Separate dashboards for manufacturers, distributors,
pharmacies, and admins. Each user can track batches, view status, and resolve
issues, whereas Admins can view the entire supply chain. Users can search and
sort batches based on parameters such as batch ID, status, timestamp of arrival
or departure, and more for the detection of anomalies, which helps in faster issue
resolution, effective monitoring, and smoother navigation.
• Medicine Recall Flow: Admins can initiate a recall for compromised or defective
batches, and all those involved in production, transportation, and retail of the batch
get instructed with actions to be taken accordingly, and are able to track recall
progress in real time.
• Supply Chain Map View: A map visualisation using Leaflet API integration
shows the geographic movement of each batch through the supply chain, whereas
Chart.js integration provides analytics such as batch distribution, status counts,
and timelines, for a complete interpretation of the entire chain flow, for both the
users and the public.
Technology stack
• HTML, CSS, JavaScript (for building most of the frontend interface and UI)
• Firebase Authentication (for secure, role-based user login)
• Firebase Firestore (for storing batch data and syncing logs in real time)
• Firebase Storage (for uploading verification certificates and shipment documents)
• CryptoJS (SHA-256 hashing) (for generating and linking block hashes) Client-side
QR code generation library (for creating QR codes for public batch verification)
• Leaflet API and Chart.js (for map-based tracking and visual analytics)
• Metamask Authentication (for optional decentralised identity verification, alongside
Firebase Authentication)
Brief Implementation Details
The system uses CryptoJS to generate SHA-256 hashes for hashing data and linking by
hashing the hash of the previous block with the data of the current block (generated by
either the distributor or the pharmacy, as the manufacturer creates the starting(genesis)
block that the distributor uses to link to with its block, which is then used to link with
the pharmacy’s block). Manufacturers create the genesis block for each batch. When
distributors update shipment information or pharmacies confirm delivery, new blocks are
appended, hashed, and linked using CryptoJS. Each block contains event data, times-
tamp, previous hash, and current hash generated as SHA-256(previousHash + event-
DataString). Firestore stores all event data along with the timestamp, previous hash,
and current hash of each block as append-only logs. A public QR-based verification page
is used to display map and analytics visualisations for the scanned batch, which are imple-
mented using Leaflet API and Chart.js, while fetching all blocks and recomputing hashes
from scratch using CryptoJS to check for tampering and verify chain integrity, which
is also displayed in the resulting verification page. Dashboards use real-time Firestore
listeners, whereas role-based authentication for manufacturers, distributors, pharmacies,
and admins is managed using Firebase Authentication and Metamask Authentication.
